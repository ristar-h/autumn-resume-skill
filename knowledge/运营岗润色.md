# 实习/工作经验/项目经历（运营岗）

解读用户的运营经验

## 结构

如果是实习/工作经历，标题写清楚：公司名称、职位、时间段。如果是项目经历（比如某次大促活动、内容专题、社群项目），标题写清楚项目名称与时间。

以项目制填写。比如写「XX 活动」，下面用 list 写清这几类信息：

- 活动/项目的背景与目标（要提升什么指标）
- 用户在其中的职责与关键动作
- 数据结果（可衡量、可归因）

以上是**要覆盖的信息维度**，不是固定的 bullet 标签。是否加「背景」「结果」这类前缀、用什么措辞，按项目实际内容判断，不要每个项目都套同一组词。

## 内容优化表述

做运营最关注：**动作 → 指标 → 结果**的因果链条能不能讲清楚。

运营同学的重点关注点：

1. **目标定义**：这次动作是要拉新、促活、转化，还是复购？目标是哪一个北极星指标。
2. **人群与场景**：面对什么用户、什么场景（新老用户、什么触达渠道、什么转化路径）。
3. **动作设计**：具体做了什么（活动机制、内容选题、私域 SOP、投放策略、增长实验）。
4. **数据结果**：可靠的指标、量级、对比基线（同比/环比/AB 对照），以及**归因**——为什么是你的动作带来了这个结果，而不是外部因素。
5. **复盘沉淀**：哪些做法可复用、可 SOP 化，哪些是踩坑教训。

## 结合 JD 的定点润色

核心：经历是素材，JD 是镜头，润色是选镜头角度。不改写事实，不把 JD 的词硬塞进简历，而是把经历里与 JD 匹配的侧面加重、置前、强化措辞。

### JD 信号词 → 强调角度

| 细分方向 | JD 信号词 | 应强调的侧面 |
|---|---|---|
| 用户增长 | 拉新、获客、渠道、投放、ROI、LTV、CAC、增长实验 | 渠道选择依据、投放素材迭代、AB 测试、成本控制、单位经济模型 |
| 用户运营 | 留存、活跃、召回、生命周期、用户分层、RFM | 分层策略、召回触达节奏、留存曲线变化、干预动作与效果 |
| 内容运营 | 选题、创作、爆款、CTR、完播率、粉丝增长、账号定位 | 选题方法论、爆款拆解、内容矩阵搭建、跨平台适配 |
| 活动运营 | 活动策划、大促、玩法、承接、转化路径、参与度 | 活动机制设计、承接页转化率、目标达成率、复盘沉淀 |
| 私域/社群 | 社群、企微、SOP、复购、私域转化、KOC | 社群分层、SOP 迭代、单群 GMV/复购率、KOC 培育 |
| 电商运营 | GMV、客单价、退货率、店铺权重、类目、直播 | 选品逻辑、直播转化率、店铺搜索排名、供应链协同 |
| 数据/策略运营 | 用户画像、AB 测试、指标体系、看板、洞察 | 指标拆解、实验设计、数据洞察→动作闭环 |
| AI 运营 | 用户反馈、Prompt 优化、Agent 调优、内容审核策略 | 反馈闭环、策略迭代速度、模型效果指标 |
| 通用（所有方向） | 跨团队、推动、Owner、结果导向、复盘 | 怎么协调资源、推动上线、复盘沉淀 |

### 边界规则

1. 只能调角度 / 权重 / 措辞，不能新增不存在的事实（呼应「证据规则」）
2. 与 JD 错开的侧面，跳过不强套；只强化能对的，绝不硬凑
3. 经历与 JD 完全没有匹配侧面时，从「学习能力 / 可迁移」角度补，并明确标注这是迁移而非已有经验

## 证据规则

将团队产出归属于团队。仅在用户的描述支持时，才使用 "主导（led）"、"负责（owned）"、"共同开发（co-developed）"、"支持（supported）"或"贡献（contributed）"。

不得编造 GMV、拉新数、留存率、ROI、粉丝量等指标。若不掌握精确数据，用「量级」或「区间」而非具体数字（如"月活规模 10 万+"而非"月活 12.3 万"）。

区分**实际业务成果**与课程作业、竞赛策划、模拟运营方案。后者要显式标注（如"课程模拟项目"）。

涉及内部数据（GMV、ROI、投放预算等）保持在合适的抽象层级，明确标注为内部数据或已脱敏。

当素材与用户最新澄清冲突时，以用户澄清为准。

## 好的表述案例

**某电商公司 · 用户增长实习生 · 2024.06 - 2024.09**

**项目：新用户首单转化率提升**

- 背景：新用户首单转化率停在 15% 附近 3 个月，需在旺季前拉高至少 3pp
- 拆解：把首单漏斗拆成"到达 → 加购 → 下单 → 支付"四步，定位加购→下单是最大流失点（跳失 42%）
- 动作：AB 测试三版承接页文案 + 首单立减券位置，A 组沿用旧版、B/C 组两种改版；同步优化购物车 SKU 推荐逻辑
- 结果：C 组胜出，首单转化率从 15.2% 提升至 19.6%（+4.4pp），大促期间沉淀为默认页面

**项目：老客召回私域 SOP**

- 主导 45 天流失老客召回，按 RFM 分层为高价值/普通/沉睡三档
- 高价值档使用企微 1v1 + 专属券，普通档走公众号推文 + 通用券，沉睡档做短信试探
- 高价值档 45 天召回率 28%，普通档 12%，沉睡档 3%——沉睡档投入产出比不划算，后续不再投入

注意上面两个项目的写法差异：第一个项目层次多，用了「背景/拆解/动作/结果」引导阅读；第二个项目逻辑本身清晰，就直接写 bullet 不加标签。**两种都对，按内容需要选择，不要统一套模板。**
